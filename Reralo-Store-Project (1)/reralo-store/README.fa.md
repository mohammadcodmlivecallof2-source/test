# فروشگاه Reralo — راهنمای نصب و انتشار

این پروژه یک فروشگاه فارسی RTL با رابط واکنش‌گرا، کاتالوگ محصولات، سبد خرید، ثبت سفارش سمت سرور، دیتابیس SQLite، پیگیری سفارش، پنل مدیریت و اعلان تلگرام است.

## نکته مهم درباره Weejur

Weejur از GitHub Pages برای میزبانی فایل‌های استاتیک استفاده می‌کند و سرور Node.js یا دیتابیس اختصاصی اجرا نمی‌کند. بنابراین این پروژه را نمی‌توان با چسباندن فقط HTML در Weejur به فروشگاه کامل تبدیل کرد. پوشه `public` می‌تواند در Weejur منتشر شود، اما برای APIها باید بک‌اند را روی میزبانی Node.js اجرا کنید و سپس فرانت‌اند را به API آن میزبان متصل کنید. این بسته در حالت پیش‌فرض، فرانت‌اند و بک‌اند را با یک آدرس ارائه می‌کند تا تنظیمات CORS لازم نباشد.

## امکانات پیاده‌سازی‌شده

- فارسی، راست‌چین، واکنش‌گرا و مناسب موبایل
- دسته‌بندی، جست‌وجو و فیلتر محصولات
- انتخاب رنگ، سایز و تعداد
- سبد خرید سمت مرورگر و محاسبه مبلغ
- اعتبارسنجی اطلاعات سفارش در سمت سرور
- ذخیره دائمی سفارش و اقلام در SQLite
- کد پیگیری یکتا و صفحه پیگیری بدون افشای آدرس/شماره تماس
- ورود پنل مدیریت با نشست امن و کوکی HttpOnly
- فهرست و جست‌وجوی سفارش‌ها، تغییر وضعیت، کد رهگیری پستی، CSV
- افزودن محصول و غیرفعال‌کردن محصول
- ارسال اعلان تلگرام و امکان تلاش مجدد از پنل
- Helmet، محدودیت نرخ درخواست‌ها و محدودیت اندازه ورودی

## پیش‌نیاز

Node.js نسخه 20 یا جدیدتر. روی رایانه نصب و اجرا کنید؛ روی موبایل می‌توانید فایل‌ها را در GitHub بارگذاری کنید و از میزبان Node.js استفاده کنید.

## اجرای محلی

1. فایل ZIP را استخراج کنید.
2. یک کپی از `.env.example` با نام `.env` بسازید.
3. مقادیر محرمانه را در `.env` قرار دهید.
4. در پوشه پروژه اجرا کنید:

```bash
npm install
npm start
```

سپس `http://localhost:3000` را باز کنید.

### تنظیم مدیر

برای توسعه محلی، مقدار `ADMIN_USERNAME` و `ADMIN_PASSWORD` در `.env` استفاده می‌شود. در محیط production باید از هش bcrypt استفاده شود:

```bash
npm run create-admin
```

این دستور هش را چاپ می‌کند. مقدار `ADMIN_PASSWORD_HASH` چاپ‌شده را در تنظیمات محیطی میزبان قرار دهید و `ADMIN_PASSWORD` را از محیط production حذف کنید. رمز باید حداقل ۱۲ کاراکتر و منحصربه‌فرد باشد. در محیط production ورود با رمز متنی عمداً غیرفعال است.

### راه‌اندازی اعلان تلگرام

1. در BotFather ربات `@Reralobot` را ساخته باش و توکن آن را دریافت کن.
2. از حساب مدیر به ربات پیام `/start` بده تا اجازه ارسال پیام خصوصی به ربات ایجاد شود.
3. شناسه عددی چت مدیر را از یک ربات معتبر دریافت کن یا با روش رسمی `getUpdates` پس از ارسال پیام به ربات بررسی کن.
4. در تنظیمات محیطی سرور، `TELEGRAM_BOT_TOKEN` و `TELEGRAM_CHAT_ID` را ثبت کن. هرگز این مقادیر را در `public/app.js` یا HTML قرار نده.
5. پس از ثبت سفارش، اعلان به مدیر ارسال می‌شود. اگر تلگرام در دسترس نباشد، سفارش همچنان در دیتابیس ذخیره می‌شود و وضعیت اعلان ناموفق می‌شود؛ مدیر می‌تواند از پنل تلاش مجدد کند.

## انتشار روی میزبان Node.js

یک سرویس میزبانی انتخاب کنید که Node.js 20+ و فضای ذخیره‌سازی پایدار برای SQLite را پشتیبانی کند (persistent disk/volume). فایل‌های پروژه را به مخزن خصوصی GitHub خود منتقل کنید و مخزن را به سرویس میزبانی متصل کنید.

- Build command: `npm install`
- Start command: `npm start`
- Environment: `NODE_ENV=production`
- `BASE_URL`: آدرس HTTPS نهایی
- `SESSION_SECRET`: رشته تصادفی طولانی حداقل ۳۲ کاراکتری
- `ADMIN_USERNAME`: نام کاربری مدیر
- `ADMIN_PASSWORD_HASH`: هش ساخته‌شده با `npm run create-admin`
- `TELEGRAM_BOT_TOKEN`: توکن ربات (محرمانه)
- `TELEGRAM_CHAT_ID`: شناسه عددی چت مدیر
- `DATABASE_PATH`: مسیر داخل دیسک پایدار، برای مثال `/var/data/reralo.sqlite`
- `SHIPPING_FEE_TOMAN`: هزینه ارسال به تومان

**دیتابیس باید روی دیسک پایدار باشد.** اگر میزبان فایل‌سیستم موقت داشته باشد، اطلاعات SQLite ممکن است پس از deploy/restart از بین برود. در آن صورت باید به PostgreSQL مدیریت‌شده مهاجرت کرد.

## انتشار Weejur

برای نسخه نمایشی فقط پوشه `public` را در Weejur بارگذاری کن. این نسخه بدون بک‌اند نمی‌تواند سفارش واقعی ثبت کند. برای فروشگاه واقعی، یا کل پروژه Node.js را روی میزبان مناسب اجرا کن، یا فرانت‌اند را روی Weejur بگذار و مسیر API را در `public/app.js` به آدرس بک‌اند امن خودت متصل کن. اگر فرانت‌اند و بک‌اند روی دامنه‌های متفاوت باشند، باید CORS، کوکی نشست و CSRF را به‌صورت مناسب پیکربندی و آزمایش کرد؛ راه ساده‌تر استفاده از یک دامنه برای هر دو است.

- `GET /api/products/:id`
- `POST /api/orders`
- `GET /api/orders/track/:code`
- `POST /api/admin/login`
- `GET /api/admin/orders`
- `GET /api/admin/orders/:id`
- `PATCH /api/admin/orders/:id`
- `POST /api/admin/orders/:id/resend-telegram`
- `GET /api/admin/stats`
- `GET/POST/PUT/DELETE /api/admin/products...`
- `GET /api/admin/export.csv`

## قبل از فروش واقعی

این پروژه یک پایه کاربردی است، نه گواهی ممیزی امنیتی. پیش از دریافت سفارش واقعی:
- روی HTTPS منتشر و همه متغیرهای محیطی را تنظیم کن.
- دیسک پایدار و پشتیبان‌گیری منظم دیتابیس را فعال کن.
- قوانین مرجوعی، تعویض، حریم خصوصی و زمان ارسال را دقیق و واقعی بنویس.
- درگاه پرداخت معتبر را با تأیید سمت سرور اضافه کن؛ این نسخه درگاه پرداخت ندارد و سفارش را به‌عنوان درخواست خرید ثبت می‌کند.
- برای استفاده تجاری، تست امنیتی، تست بار، سیاست CSRF متناسب با معماری و پایش خطاها انجام شود.
- عکس‌ها فعلاً از Unsplash بارگیری می‌شوند؛ برای استفاده تجاری بهتر است عکس‌های دارای مجوز مناسب یا عکس‌های اختصاصی محصولات جایگزین شوند.
- قیمت و هزینه ارسال در UI باید با مقدار سرور همگام بماند. در این نسخه هزینه ارسال در سرور با `SHIPPING_FEE_TOMAN` تنظیم می‌شود؛ اگر آن را تغییر دادی، مقدار نمایشی در `public/app.js` را هم به‌روزرسانی کن.
